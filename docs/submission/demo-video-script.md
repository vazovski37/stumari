# Demo video script (≤ 3:00, live product)

Show the **live product on devnet**: real screens and real transactions, no slides. Record each beat as its own clip, cut out waiting time, and keep the final cut **≤ 3:00** (target 2:50). Narration runs at about 2.5 words per second, so each beat's word budget is its length in seconds × 2.5; every line below fits its budget, and numbers take longer to say than to read. Wording follows [vision-and-positioning.md](../product/vision-and-positioning.md): say "stablecoin checkout for merchants". Never call it a "travel app" or an "escrow app", and claim no "firsts".

## Prep (day before)

- [ ] Web app deployed on devnet with `STUMARI_DEMO_MODE=true` ([runbook](../plan/runbook.md)). The demo hotel `stumari-demo` (Stumari Demo Guesthouse) is seeded by bootstrap ([configuration.md](../architecture/configuration.md#demo-data-seeded-by-scriptsbootstrapts)).
- [ ] Two browser profiles, each with its own funded **Test wallet**:
  - **Guest A**: a new wallet with no history.
  - **Guest B**: a **repeat guest** whose wallet has one `released` stay at the demo hotel. The model's wallet-history features are `is_repeated_guest` and `previous_bookings_not_canceled` ([pricing-and-risk-model.md](../architecture/pricing-and-risk-model.md#features--only-what-stumari-knows-at-quote-time)); the shipped model prices 1, 2 and 3 released stays identically, so one is enough. Create it the day before with a same-day booking and the 2-minute demo release delay (see the release beat below).
  - Connect each wallet **before** clicking "See prices", so the quote is priced with that wallet's history (`buyer_wallet`). Cancellations are *not* a model input, so don't narrate "this guest cancelled before".
- [ ] **Confirm the direction of the repeat-guest difference** in a rehearsal with the same room and dates, check-in about 6–10 days out. With the shipped model the Flexible gap between a new and a repeat wallet *shrinks* as lead time grows (on a 130 USDC base: about 0.63 USDC at 6 days, 0.39 at 10, 0.25 at 60, 0.13 at 150), so don't use far-off dates for this beat. Wallet history can only lower the model's cancellation risk (monotone constraint), so Guest B's **Flexible** price is usually *lower* (not guaranteed: lower early-window risk shifts weight to later windows) than Guest A's, and Guest B's Non-refundable discount smaller. Write both Flexible prices down. If Guest B's Flexible price is not lower, or the gap is too small to see, try a shorter lead time (about 6 days). If it still doesn't show, cut the "Guest B" sentence and don't narrate a difference. Never fake a number.
- [ ] **Cancel beat**: use check-in dates 4–6 days out for the pay and cancel beats. Standard then refunds 50%, and Explorer shows both the guest's refund and the hotel's share. Before cancelling, wait until the booking shows **Confirmed**; a *pending* booking always refunds 100%.
- [ ] **Release beat**: set the demo hotel's check-in time a few minutes ahead, make a same-day booking, and let `release_delay_secs = 120` pass. The payout is then due on camera ([escrow-program.md](../architecture/escrow-program.md#constants)).
- [ ] The landing page shows the corrected statistics ("27% of ordinary bookings", "1,579,764"; never "37% of bookings" or "1.58M") — the apps/web landing-copy item in [backlog.md](../plan/backlog.md) must have shipped before recording.
- [ ] **iCal beat**: the seeded demo data has no import URLs. On `/dashboard/{hotelId}` (Units panel), give one demo unit an import URL with a few blocked nights — e.g. the export feed of another demo unit that holds a test booking, or any public test `.ics` — and run **Sync calendars now** once in rehearsal. Unless it is a real Booking.com test calendar, narrate and label it as an OTA-style iCal feed, not Booking.com.
- [ ] Calibration plot open in a tab (the web app renders `ml/reports/reliability.json`; a PNG is optional). The model numbers below are copied from [ml/reports/metrics.md](../../ml/reports/metrics.md) (model `hazard-gbdt-2026-09-25`, 36,294 held-out bookings arriving January–August 2017). If the model is retrained, copy the new numbers into the narration and the overlay.
- [ ] Claude Desktop with the Stumari MCP server configured and a funded devnet agent key ([runbook](../plan/runbook.md#8-mcp-server-for-claude-desktop)).
- [ ] Solana Explorer on `?cluster=devnet`. Browser zoom 125%. Close notifications.

## Recording on the local chain (when devnet is not funded)

On 2026-10-13 the devnet operator had no SOL and the faucets were rate-limited, so the demo was prepared on the **local Solana chain** instead: the same program, real transactions and test USDC, running in Docker on the recording laptop. Nothing is faked. The guest pages show "Demo on a local test chain" in their banner.

1. Docker Desktop running. Then `pnpm --filter @stumari/scripts bootstrap --cluster localnet --reset` for a fresh chain whose clock matches wall time.
2. Start the web app on the port in `NEXT_PUBLIC_SITE_URL` (Sign-In With Solana checks that host). Only one `next dev` can run per app folder.
3. `pnpm --filter @stumari/scripts demo-seed -- --url <that URL>` seeds a released stay (Guest B), a confirmed stay and a cancelled stay ([scripts/README.md](../../scripts/README.md#demo-seed)).
4. Browser profiles: **Guest A** is a fresh profile with the Test wallet. Load **Guest B** and **Hotel** with the console lines in `onchain/keys/demo-browser-wallets.txt` (gitignored).
5. Explorer links use `?cluster=custom&customUrl=http://127.0.0.1:8899`. Chrome may ask to allow access to devices on the local network: allow it once before recording.
6. Never move the chain clock (`timetravel`) before recording: quotes would fail with `QuoteExpired` until the next `--reset`.

Narration: say "a local Solana test chain" wherever the script says devnet, and keep the honest-limits beat. The public link (`https://stumari.azurewebsites.net`) shows the landing only until devnet is funded, so the submission's access instructions must say so.

## Don't

- Don't show slides or mockups. Every screen is the deployed app, Explorer, Claude Desktop, or the plot file.
- Don't say "first", "no one else", or that independents cannot get cancellation pricing (Hopper reaches them through Cloudbeds).
- Don't say "no Stumari key can redirect funds" without both limits from [security.md](../architecture/security.md#honest-limits-of-the-trust-property-say-these-out-loud): the program is upgradeable by Stumari during the pilot, and disputed funds depend on the arbiter key.
- Don't round or restate the statistics: "27% of ordinary bookings (37% overall incl. no-shows and group blocks)", and the model numbers exactly as in `ml/reports/metrics.md`.
- Don't show traction you do not have. Don't show private keys, `.env` files or a seed phrase on screen.
